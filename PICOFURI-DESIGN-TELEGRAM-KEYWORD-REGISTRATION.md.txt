## 1. 背景と目的

### 現状の問題

- キーワード登録・編集は Web UI (`/keywords` 画面) のみ。デスク前でないと使えない
- 1キーワード = 1 item_code の単一紐付け → `n` サフィックス複数カタログが集計漏れ
- セノッピー系で「CSV実績と通知数字の不整合」の根本原因

### ゴール

- Telegram で新規キーワード登録が完結する（モバイル完結）
- 1キーワードに複数 item_codes を紐付け可能にする
- 既存キーワードも新体系に移行、`n` 変種の自動抱き合わせを効かせる

### 対象外（別タスク化）

- `/edit` / `/delete` / `/search` / `/scan` コマンド（第二弾）
- 除外キーワード・上限価格の UI（既存 Web UI で運用継続）
- プラットフォーム選択 UI（デフォルト「メルカリ+Yahoo!フリマ」で固定）

## 2. 設計

### 2.1 DB変更（Phase 1）

`keywords` テーブルに `item_codes` カラム追加（TEXT、カンマ区切り）。既存 `item_code` カラムは **残す**（後方互換、Phase 2 で移行後も当面保持）。

```sql
ALTER TABLE keywords ADD COLUMN item_codes TEXT;
CREATE INDEX idx_keywords_item_codes ON keywords(item_codes);
```

### 2.2 既存キーワード移行（Phase 2）

|状態                                         |移行方針                                              |
|-------------------------------------------|--------------------------------------------------|
|`item_code` が NULL                         |`item_codes` も NULL                               |
|`item_code` が単一値（例: `2314-001811`）         |`item_codes = '2314-001811'`                      |
|`item_code` 側に `n` 変種が crossmall_items にあれば|`item_codes = '2314-001811,2314-001811n'`（自動抱き合わせ）|

移行スクリプトは冪等（再実行しても同じ結果）。

### 2.3 検索API（Phase 3）

```
GET /api/crossmall/items/search?q=<キーワード>&limit=50
```

レスポンス:

```json
{
  "count": 3,
  "items": [
    {
      "item_code": "2314-001247",
      "item_name": "セノッピー チュアブル SENOPPY CHEWABLE 30日分 30包",
      "base_code": "2314-001247",
      "stock": 0,
      "has_n_variant": true,
      "n_variant_item_code": "2314-001247n"
    },
    ...
  ]
}
```

実装：`crossmall_items` を `item_name LIKE '%<q>%'` で部分一致検索。`has_n_variant` は同じ `base_code` で末尾 `n` の item_code が存在するか。

### 2.4 Telegram FSM コア（Phase 4）

#### 状態遷移

```
IDLE
  ↓ /add
ASK_KEYWORD
  ↓ (テキスト入力)
ASK_SEARCH_QUERY
  ↓ (テキスト入力)
SELECT_ITEMS
  ↓ (チェックボックス操作 → 完了ボタン)
CONFIRM
  ↓ (登録 / やり直し / キャンセル)
DONE (または IDLE に戻る)
```

#### セッション管理

メモリ内 `Map<userId, { step, data, createdAt }>`。10分でタイムアウト自動破棄。

#### 権限チェック

`process.env.TELEGRAM_ADMIN_ID` と一致するユーザーのみ。不一致は無視（既存 Bot と同じ方式）。

#### Inline Keyboard 制約

Telegram 仕様: 1メッセージ最大100ボタン、推奨 1行5ボタン以下。  
今回は 1行1商品 + 完了/キャンセルの2ボタン。50件超の検索結果はページネーション不要（件数多いなら再検索を促す）。

### 2.5 管理コマンド（Phase 5）

|コマンド     |動作                                 |
|---------|-----------------------------------|
|`/list`  |登録済みキーワード一覧表示（ID、name、紐付けSKU数、監視状態）|
|`/cancel`|進行中のセッションをリセット                     |
|`/help`  |コマンド一覧                             |

### 2.6 ScrapingService 連携（Phase 6）

現行 `ScrapingService.getStockAndPrice(item_code)` 単一呼び出しを、`item_codes`（配列）受け取りに変更。内部で `CrossmallDbService.getStockAndPriceByBaseCode()` を活用。

通知文生成も複数 item_codes を意識する必要があるか調査。base_code集約で十分なら呼び出し側の変更のみ。

## 3. 実装フェーズ

### Phase 1: DBマイグレーション

**タスク:**

1. `server/migrations/20260418000001-add-item-codes-to-keywords.js` 作成
- `item_codes` TEXT カラム追加
- インデックス作成
1. `server/models/Keyword.js` に `item_codes` フィールド追加
1. `npx sequelize-cli db:migrate` 実行

**セルフテスト:**

- [ ] `sqlite3 database.sqlite ".schema keywords"` で `item_codes` カラムが追加されている
- [ ] 既存テーブル他カラムは変更なし
- [ ] ロールバック: `db:migrate:undo` でカラム消失確認 → `db:migrate` で再作成
- [ ] `Keyword.findAll()` で `item_codes` プロパティが含まれる（NULL許容）

-----

### Phase 2: 既存キーワード移行

**タスク:**

1. `server/scripts/migrate-keywords-to-item-codes.cjs` 作成
1. 処理内容:
- 全 keywords 取得
- 各キーワードの `item_code` を読む
- `crossmall_items` で `base_code` が一致する全 item_code（`n` 変種含む）を取得
- カンマ区切りで `item_codes` カラムに書き込み
- 冪等性（再実行で同じ結果）
- 処理件数とサマリ出力
1. 実行: `node server/scripts/migrate-keywords-to-item-codes.cjs`

**セルフテスト:**

- [ ] 移行前後のキーワード件数が一致
- [ ] `item_code` が設定されているキーワードすべてで `item_codes` が NULL でない
- [ ] `item_code = '2314-001811'` のキーワードの `item_codes` に `2314-001811` が含まれる（`n`変種があれば併記）
- [ ] `item_code` が NULL だったキーワードは `item_codes` も NULL（変更なし）
- [ ] 再実行で結果変化なし（冪等性）
- [ ] 具体例として「りそうのコーヒー」または「ToyLaBO」などで結果を抜粋報告

-----

### Phase 3: 検索API

**タスク:**

1. `server/routes/crossmall.js` 作成（既存になければ）
1. エンドポイント実装: `GET /api/crossmall/items/search`
- クエリ `q` で部分一致検索（必須、空なら400）
- クエリ `limit`（省略時50、最大100）
- レスポンスは §2.3 の形式
1. `server/app.js` にルート登録: `app.use('/api/crossmall', require('./routes/crossmall'));`
1. 動作確認: `curl http://localhost:3000/api/crossmall/items/search?q=セノッピー`

**セルフテスト:**

- [ ] `q=セノッピー` で複数件ヒット
- [ ] `q=XYZ`（存在しない） で `count=0, items=[]`
- [ ] `q=` (空) で 400 エラー
- [ ] `limit=5` で最大5件に制限される
- [ ] `has_n_variant` が `2314-001247` で true、`2314-001636` で false
- [ ] `n_variant_item_code` が `has_n_variant=true` の時のみ存在

### Phase 6: ScrapingService 側の複数 item_codes 対応

1. `CrossmallDbService.getStockAndPriceByBaseCode(baseCode)` を呼ぶ
1. 通知文に影響する変更点を確認・調整

**セルフテスト:**

- [ ] `item_codes` が複数のキーワードで集約された在庫・販売数が取れる
- [ ] `item_codes` が単数のキーワードでも正常動作

- [ ] 通知文の数字が Phase 6 修正前と一致（単一item_codeのキーワードの場合）
- [ ] セノッピー系（`n`変種あり）で集約後の数字が CSV と整合

- Telegram polling モードは HTTPS 不要、再起動で polling 再開
